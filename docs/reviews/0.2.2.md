# Follow-up review of 0.2.1 (for corrective release 0.2.2)

Reviewed 2026-10-19 against commit `c541e06` (version 0.2.1), the original product concept and `RELEASE_PLAN.md`. Main had not changed since the review, so every finding was open when release 0.2.2 started. Status below is as of the 0.2.2 release.

This review found household-state and tax-eligibility errors that the 0.2.1 review missed, and it reopens S2 from [0.2.1.md](0.2.1.md). Release 0.2.2 fixes these findings before any further tax or cost coverage is added. Parts that belong with later work are scheduled in the release named in the table, with the reason.

**Severity:** High = wrong or misleading figures. Medium = a test or source gap on money logic, or confusing UX. Low = tidy-up.

## Acceptance for the findings

- **F1:** removing the partner removes joint treatment, for two earners → one adult, one earner plus partner → one adult, and a restored profile. A one-earner married household keeps joint treatment while the partner is present.
- **F2:** equivalent households give equal results. Tests for unmarried parents, married parents, single parents and a non-earning partner, with independently worked examples for each supported filing arrangement.
- **F3:** a registered partnership does not produce federal joint filing. Head of household needs the confirmation. Reordering income entries does not change household tax.
- **F4:** tests at the age-band boundaries used by the rules. Unsupported situations are named in the result.
- **F5:** reset tested after rent, take-home and overrides in several cities; default tax resumes; old overrides do not come back on another city.
- **F6:** missing childcare, healthcare and transport each give an accurate incomplete state, and every suggested action exists.
- **F7:** reducing children updates the daycare count and its maximum; input, saved state and breakdown agree; other invalid inputs are not accepted silently on rerender.
- **F8:** a tax file missing a required field fails validation; malformed nested values fail before runtime; stale data is handled as the release policy says.
- **F9:** a malformed link does not stop the app starting.

## Planning recommendations accepted

- The roadmap is rebalanced so a five-city pilot runs the whole Explore → Find → Compare journey before coverage expands.
- Pilot cities: Helsinki, Berlin, Madrid, Austin and Hermosillo. Hermosillo stays in the pilot because Mexico is a location of high personal interest to the owner, so the Mexican employment tax model moves into the pilot release. - Methodology notes ship with the numbers they explain, not in a later release.
- The official-calculator cross-check (S7) is scheduled in a review release instead of the backlog.
- Maintenance reviews check data meaning, supported household scenarios and independence of test evidence, not only a green suite.
- Browser and accessibility checks are added release by release, not left to 1.0.
- Matching within €1 a month means the calculation is implemented correctly; it does not claim real-world take-home is accurate to €1.
